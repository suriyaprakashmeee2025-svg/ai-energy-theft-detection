# Project Report
## AI-Based Energy Theft / Abnormal Consumption Pattern Detection

### 1. Abstract
This project develops an educational machine-learning pipeline that detects unusual electricity-consumption intervals from meter readings. A synthetic dataset is generated with hourly consumption, temperature, time features, and a small number of injected unusual readings. The data is cleaned, transformed into useful features, and analyzed using an Isolation Forest model. The system outputs anomaly scores, flags unusual intervals, evaluates the flags against known synthetic labels, and presents the results in a Streamlit dashboard.

### 2. Problem statement
Manual inspection of many electricity readings is difficult. Unusual consumption may be caused by meter errors, data problems, changing household routines, equipment faults, or possible unauthorized activity. The aim is to automatically screen readings and prioritize intervals for human review.

### 3. Objectives
1. Create or use an electricity-consumption dataset.
2. Clean missing, invalid, and time-related data.
3. Explore daily and hourly usage patterns.
4. Engineer time-based and historical-average features.
5. Train an anomaly-detection model.
6. Produce anomaly scores and flagged intervals.
7. Evaluate performance and false alarms.
8. Show trends and results in a dashboard.
9. Document limitations and responsible use.

### 4. Tools and technologies
- Python: main programming language
- Pandas and NumPy: data processing
- Scikit-learn: Isolation Forest and evaluation metrics
- Matplotlib: charts
- Streamlit: dashboard
- Joblib: save the trained model

### 5. Dataset and assumptions
The bundled data is generated by `generate_data.py`. It contains hourly readings for multiple simulated meters. A daily pattern is created with morning and evening peaks, plus random noise and temperature context. Some readings are deliberately changed to simulate unusual spikes or drops. `is_simulated_anomaly` is the known evaluation label; it is excluded from model features.

These are educational assumptions, not measured utility data. The injected patterns are not a complete model of energy theft.

### 6. Preprocessing
- Convert timestamps to datetime.
- Convert consumption to numeric values.
- Remove rows with missing timestamp, meter ID, or consumption.
- Remove negative consumption values.
- Sort records by meter and time.
- Use training-set medians to fill missing feature values.

### 7. Exploratory data analysis
The training script creates:
- `reports/consumption_trend.png`: hourly consumption trend for a sample meter.
- `reports/anomaly_scores.png`: score distribution for normal-labelled and injected-anomaly readings.
- `reports/confusion_matrix.png`: predicted flags compared with synthetic labels.

### 8. Feature engineering
The model uses:
- Consumption in kWh
- Temperature
- Hour of day
- Day of week
- Month
- Weekend indicator
- Rolling 24-hour mean
- Difference from rolling mean
- Ratio of consumption to the meter's median consumption

### 9. Machine-learning method
Isolation Forest is an unsupervised anomaly-detection algorithm. It isolates data points through random feature and split selection. Unusual observations tend to be isolated in fewer splits. The project uses `contamination=0.02` as an initial estimate that around 2% of test readings may be unusual. This is a configurable modelling assumption, not a known real-world theft rate.

The data is split chronologically: earlier observations are used for fitting and later observations are used for evaluation. The model does not use the synthetic label as an input.

### 10. Evaluation
The script reports:
- **Precision:** of the readings flagged, what fraction match injected anomalies?
- **Recall:** of injected anomalies, what fraction were flagged?
- **F1-score:** harmonic mean of precision and recall.
- **False-positive rate:** normal-labelled readings incorrectly flagged divided by all normal-labelled readings.
- Confusion matrix: true positives, false positives, true negatives, false negatives.

Run `python train_model.py` to obtain actual metrics in `outputs/evaluation_metrics.json`. Metrics are intentionally not prefilled here because they must be calculated from the generated dataset and model run. Results measure detection of the artificial patterns only.

### 11. False-positive analysis
A false positive is a reading flagged by the model even though it is normal according to the synthetic label. Causes can include a genuine usage increase, unusual but legitimate schedules, weather-driven cooling, visitors, holidays, or noisy data. A false positive can also arise because the synthetic definition of “normal” is simplified.

Recommended improvements:
- Inspect flagged intervals with surrounding readings.
- Compare against the meter's own historical pattern.
- Tune the contamination setting on validation data.
- Evaluate different seasons and household types.
- Keep a human review stage.
- Never treat a flag alone as evidence of wrongdoing.

### 12. Dashboard
Run `streamlit run app.py` to see meter filters, trend charts, flagged intervals, anomaly scores, and evaluation metrics.

### 13. Limitations and responsible use
- Synthetic data cannot establish real-world accuracy.
- An anomaly is not equivalent to theft.
- Results may be biased by meter type, season, home size, occupancy, and missing data.
- Only authorized, privacy-protected data should be used.
- Real deployments require validation on representative labelled data, monitoring for drift, secure data handling, human review, and an appeal process.
- No automatic disconnection, penalty, or accusation should be based solely on this model.

### 14. Future scope
- Test on a reputable public dataset.
- Add meter-level energy balance where authorized feeder data is available.
- Compare Isolation Forest with Local Outlier Factor and supervised Random Forest if trustworthy labels exist.
- Add alert history and model-version tracking.
- Conduct validation across seasons and meter groups.

### 15. Conclusion
The project demonstrates an end-to-end AI workflow for screening unusual electricity consumption: dataset generation, preprocessing, feature engineering, anomaly detection, evaluation, visualization, and dashboard development. It is a learning prototype and decision-support tool, not a standalone theft-verification system.
